### 完成的決策

**1. P3 行程地圖 —— 選定 Leaflet（而非 MapLibre）。**
理由：只需「世界地圖標城市點 + 連線」，不需要 WebGL 向量渲染；Leaflet 42 KB、
API 穩定、BSD-2-Clause。圖磚起始用 OSM 官方，流量上升後換 CDN／自架，只換 tile URL。
**不用天地圖**：其唯一優勢是境內合規，而本 App 已確認為**非境內使用**；
且其免費條款以境內主體為前提，境外使用語焉不詳 → 引入反而增加不確定性。

**2. 發現地圖的真正阻塞點不是圖層，而是隱私規則。**
`models/trip.py` 只存 `destination_country` / `destination_city` 自由文字、
**沒有座標**，且 docstring 明說寬度粗化是為遵守 §2.2 精確位置隱私規則
（`docs/SECURITY.md` 列為合規項 ✅）。要標點就得加經緯度 = 提高位置精度 = 與 §2.2 衝突。
→ 必須先決定「放寬規則」或「改存城市中心點」。其次是地理編碼（含歧義處理）。
**這是一條新的資料處理鏈，不是接圖層。**

**3. 多副本前置清單補完（README 技術債 #22 / STATUS §4.1）。**

### 兩個「假失敗」（環境問題，非產品缺陷）—— 教訓要記住

1. **手動起後端時 DB 用了 `e2e_check.db`，但 `promoteToAdmin` helper 硬編碼
   `backend/e2e.db`** → 管理員測試失敗，看起來像 RBAC 壞了。
   `E2E_DB_FILE` 在 `frontend/e2e/constants.ts`，helper 用它組 `DATABASE_URL`。
   **手動起服務時必須用同一個 DB 檔名**，否則「升級了另一個 DB 的人」。
   正解：讓 Playwright 自己管服務（`npx playwright test`，不要 `E2E_NO_WEBSERVER=1`）。
2. **倉庫內沒有 `.venv`** → `resolvePython()` 回退到裸 `python`（managed 3.13.12 缺 uvicorn）
   → webServer 起不來，錯誤是 `No module named uvicorn`。
   **正解是設 `E2E_PYTHON` 指向 `.../envs/default/Scripts/python.exe`**
   （`e2e/python.ts` 的第一順位就是它）。

### 操作教訓

- **`git check-ignore` 讀的是 `.gitignore`，不是 `.dockerignore`。**
  我曾用它「驗證」`.dockerignore` 擋不擋 `.env` —— 那是**無效驗證**（結果來自 `.gitignore`）。
  正解：用 Python 自己實作 `.dockerignore` 的 pattern 語義（含 `!` 反向規則）去比對。
- **heredoc 寫 `node` 腳本會被 bash 展開 `${...}`**（`Error: Bad substitution`）。
  含 template literal 的腳本一律用 `Write` 工具寫檔再執行。（與既有的
  「不要用 heredoc 寫多行 Python 替換腳本」是同一類坑。）
- **`ENV` 只接受 `development` / `staging` / `production`**，沒有 `test`
  （`config.py` 是 Literal），傳 `test` 會在啟動時 ValidationError。
